# 2026-05-22 — CMS dashboard implementation

## Summary

Built a full Supabase-backed admin CMS for DigSolutions. Marketing site refactored into `app/(marketing)/` route group; admin lives in `app/(admin)/admin/(protected)/`.

## What shipped

### Supabase foundation
- `@supabase/supabase-js` + `@supabase/ssr` installed.
- Client/server/middleware helpers in `lib/supabase/`.
- `middleware.ts` gates `/admin/*` (except `/admin/login`) on a valid session.
- `.env.example` documents the required env vars.

### Database (`supabase/migrations/`)
1. `20260522000001_init_schema.sql` — tables, enums, triggers, helper functions (`is_admin()`, `is_editor()`).
2. `20260522000002_rls_policies.sql` — RLS on every table; anon reads only `status='published'`; editors manage all; admins delete; anon can insert leads & page_views.
3. `20260522000003_seed.sql` — seeds services, industries, case studies, insights, guides, testimonials, team, open roles, and the site_settings singleton from the existing static content.
4. `20260522000004_storage.sql` — `media` storage bucket with public-read + editor-write policies.

Tables: `profiles`, `services`, `industries`, `case_studies`, `insights`, `guides`, `testimonials`, `team_members`, `open_roles`, `leads`, `site_settings`, `media`, `activity_log`, `page_views`.

### Admin UI (`app/(admin)/admin/`)
- `login/page.tsx` — public sign-in form using `supabase.auth.signInWithPassword`.
- `(protected)/layout.tsx` — server-side `requireAdminProfile()` guard, wraps `<AdminShell>`.
- `(protected)/page.tsx` — dashboard overview with stats cards and recent leads.
- Content sections (list + new + `[slug]` or `[id]` edit + server actions):
  - `services`, `industries`, `work` (case studies with metrics), `insights`, `guides`, `testimonials`, `team`, `careers`.
- Operations: `leads` (kanban tabs + detail with status/notes), `media` (Supabase Storage grid + upload).
- Workspace: `users` (list + role select + invite), `settings` (tabbed form for brand/contact/social/SEO/pricing).
- Insights pages: `analytics` (top pages + lead funnel), `activity` (audit log timeline).

### Design system
- New admin tokens (CSS variables, dark-mode-aware) in `app/globals.css` + Tailwind config.
- Dense admin scale (`13px` body, `28px` displays).
- Reusable primitives in `components/admin/ui/`: `Button`, `Input`, `Textarea`, `Label`, `Badge`, `StatusBadge`, `Separator`, `Card*`, `EmptyState`, `DataTable`, `StickySaveBar`, `FormField`.
- Shell: `AdminSidebar`, `AdminTopbar`, `CommandPalette` (Cmd-K via `cmdk`), `ThemeProvider` (light/dark toggle).

### Marketing integration
- Contact, book-consultation, and footer newsletter forms now post via server actions → `leads` table.
- `app/api/pageviews/route.ts` + `<PageViewLogger>` write to `page_views`.
- `lib/content/fetchers.ts` provides async `getServices()`, `getInsights()`, etc. with normalized shapes and local fallback when Supabase env is missing.

### Activity log
- Every mutation (`create`, `update`, `publish`, `unpublish`, `delete`, `invite`, `status:*`) writes via `logActivity()` in `lib/admin/activity.ts`.

## Build verification

`npx tsc --noEmit` — clean.
`npx next build` — 59 routes, all green:
- 36 admin routes (dynamic, server-rendered on demand)
- 23 marketing routes (static + SSG)
- 1 API route, 1 middleware
- Largest first-load: `/admin/login` at 187 kB; marketing pages around 150 kB.

The SWC native binary warning on Windows is cosmetic — Next.js falls back to WASM.
